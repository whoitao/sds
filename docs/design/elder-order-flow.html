流程主干与兜底

6 步走完 · 3 条支线保证没有死路

主干每一步都是独立一屏，返回永远能回到上一屏；支线处理「定位失败」「不会操作」「想取消」三种最容易让老人放弃的情况。v0.5 把原来「挑柜台 → 看柜台的菜」两屏合回首页一屏：一级分类横滑、二级分类竖列、商品就在右边，三样同时在场。合掉的理由不是省步骤，而是不再需要「点进去看完再退回来换一类」——那一下返回，老人得先想起来自己是来干什么的。

电商那套底栏（首页 / 购物车 / 订单 / 我的）照标准画，但只在一级页出现——S0 和 T1。从 S1 换店一路到 S5 下完单，底栏收起，横向出口只留左上角返回。道理很实在：付钱那一屏若允许一键跳回首页，那半篮已选的菜和填好的地址怎么办，现在没人定得过。S2 和 T1 是同一个篮子，两个入口——S2 是顺着流程走到「清点」，T1 是从底栏回头找自己的菜；老人不必知道它们是同一个东西，但两边给的减号和合计必须一模一样。有了 T1，才存在「走到 S4 突然想去拿别的」再原路回来这条真实路径，不用把已填的地址从头来一遍。

v0.5 还有一处全局改动：header 中间的门店药丸顶掉了页面标题。「我在哪家店」是每一屏都成立的事实，「我在第几步」只在有下一步时成立，所以常驻的那格给了店。代价写实在这儿——屏上从此没有「怎么拿菜」「付钱」这类大字标题了，定位只能靠底栏合计那句话、减号的存在、以及右上角帮助按钮；这条已进 §3.5 待拍板。

  • 屏内文字只引用 --fs-*，没有一处裸 px。v0.3 做的事是把基准整体乘 --fs-scale: .9——旋钮只有这一个，屏内 HTML 与这张表都不用再动。

  • 触控尺寸故意不吃 --fs-scale：字号可以让用户（或家属代调）选，防误触的按钮高度不能跟着抖。--tap-nav 44px 已贴 WCAG 下限，再收就破线。
  • 已知缺口：若将来允许把 --fs-scale 调到 1 以上，--fs-hero（26 × 1.1 ≈ 28.6px）会顶不进 58px 的 .bigbtn。真要做「可调大」，--tap-* 必须同时给系数。这一版没有，先记在这儿。
  • v0.4 把界面图标定成一套 inline SVG 描边：尺寸走 .ico 的方框（19 / 22 / 24 三档），不吃 --fs-scale，颜色走 currentColor 所以选中态只要改文字色就跟着变。定义集中在 <body> 顶部的 sprite，屏内只用 <use href="#i-…"> 引用——仍然是单文件自包含，没有外部图标库。
  • 仍然不进令牌的三类图形：加减号 / 返回箭头 / 「?」这些是打字字符不是图标；模拟状态栏 13px 由 OS 绘制；商品图 .pic 故意留 emoji——那是照片占位，彩色才对，换成同粗细线稿反而分不出猪肉和豆腐。屏内唯一吃字号的角标是购物车数字，它走 --fs-body，不许落到地板以下。
  • v0.5 首页那五段是手算出来的，不是试出来的：问候 32 + 店铺图 98 + 一级横滑 66 + 左右分栏 272 + 提示条约 52 ＝ 520，加 4 段间距 40 ＝ 560，可用区 576（824 − 状态栏 40 − header 62 − 结算条 79 − 底栏 63 − 上内边距 4），余 16px。这是本文件目前最挤的一屏，--fs-scale 若往上调，第一个撑破的就是它——所以首页是全局字号机制落地时必须回归测试的第一屏。「想吃哪类」那四个字之所以挤在滑道左边而不是单独起一行，就是因为那一行 34px 这屏给不起。
  • 药丸顶掉标题是取舍，不是免费：药丸只能放 4 个字（整丸实测宽 150px，而最窄一档留给它的是 152px——S0 有铃铛、其余屏有返回，右边还压着一个帮助按钮），所以「阳光生鲜（文三路）· 步行 5 分钟 · 营业到晚上 6 点」这句话必须拆两处：店名进药丸，全称和营业信息进首页那张店铺图下面那行。分店括注从此不在每一屏都看得见，这是砍掉的代价。

  • 底栏标签：未选中 #55655A / 卡片白 = 6.18:1，选中 #2F6B47 / 卡片白 = 6.33:1，都是本表已实测过的组合，没有新面孔。
  • 描边图标不会单独产生新的对比度问题：它用 currentColor，所以它的对比度就是它所在文字色的对比度。逐对实测——底栏未选中 6.18:1、底栏选中 6.33:1、一级格与二级栏选中态和店铺 pin #2F6B47 / #E8F3EC 5.57:1、未选中付法选项与锁定态药丸 #55655A / #FCFBF6 5.97:1、微信那条 #55655A / #E8F3EC 5.44:1、提示条与帮助 6.80:1。图形只要求 WCAG 1.4.11 的 3:1，最低一项 5.44:1 仍有一倍余量；唯一压实底的成功勾是白描边 / #4C9A6A = 3.42:1，也过线。
  • 首页的选中态不是只靠颜色表达的：一级格与二级栏被选中的那一格同时改三件事——底色转 --green-soft、描边转 --green、文字转 --green-deep 且字重从 600 加到 700，未选中那格则始终带描边和投影。所以「哪一格是当前类别」不依赖看出色差，色弱或屏幕偏色也读得出来（WCAG 1.4.1 用色 / 1.4.11 非文本对比）。药丸的三种态同理：可点的带「⌄」，锁死的既没有「⌄」也退了底色。
  • 系统状态栏（9:41、电量）由 OS 绘制，不计入产品文字规格。

3.5 画这 8 屏时冒出来的、需要产品先拍板的 14 件事
  • 店铺是入驻还是自营。影响 S1 能不能承诺「线上写的有，店里真有」，也决定库存和定价归谁改。本原型按「单店自管库存」画；若改自营，只换 S1 的数据来源，主干不变。
  • 一级分类超过六个怎么办。现在滑道一屏露 3 格 + 半格，六个是画得下且不让人迷路的上限。店里若开出 8–10 个顶级分类，是让老人多滑两下，还是把米面油和调料合成一个大类？另外今天一种货都没有的空柜台、以及后台停用的分类（is_active = false），是留一格说「今天没有」还是直接隐藏——这条不定，S0 的滑道就没法验收。
  • 药丸顶掉标题之后，老人怎么确认「我在第几步」。v0.5 起除 S6 外屏上没有大字标题了，定位只剩合计那句「一共 3 样，要付」、减号在不在、以及底栏那句「下一步 · 付钱」。这三样够不够一个老人判断自己没走错，是本轮最没底的一条，也是画完才看见的代价——要补的话，只能补在合计那一行上面，而不是把标题加回来。
  • 药丸能不能全程点。本原型按「逛的时候能点、进结算就锁死」画：S0 / S2 / T1 带「⌄」，S3–S5 灰底无「⌄」。理由是换了店，已填的地址和这一篮子全作废，那一屏没人接得住。但若产品要求结算途中也能换店，就必须先定「半篮菜 + 地址怎么办」，否则锁死是唯一不骗人的画法。
  • 铃铛里装什么。S0 和 T1 画了铃铛入口，但没画它点开的屏——这是本轮新造出来的第三个空壳。装的是「店里通知：您买的鸡蛋今天到晚了」，还是「订单进度变更」，还是干脆是消息中心？若首版没有内容，这个铃铛应该删掉而不是留着等。
  • 横滑要不要加左右箭头。现在只靠「露半格」暗示还能滑。加一对 44px 的箭头最直白，但会挤掉一格半的可见数（342px 里给两侧各留 44 就只剩 2 格），对老人反而是「怎么只有两个类别」。要不要加、还是加在类别多于几个时才出现——没定。
  • 「全部 9」和「猪肉 3」的计数口径。PRD §5.4 写「商品可归属任意一级分类，也可不选分类」，所以那 9 个里可能有一件只挂了「肉」、没挂任何二级。它现在被「全部」兜住（这是选「全部置顶」要解决的问题），但会不会在「猪肉」的计数里凭空少一件——「全部 9」与「3+2+1+2+1=9」这条等式在真实数据下到底成不成立，要后端给口径。
  • 到店付现金要不要留。S4 第三条会造成线上下单、线下实收两张皮，需要店长确认。首版若砍掉，只剩微信 + 儿女代付，S4 更干净。
  • 起送金额与配送费。现在 ¥53.00 里没有任何配送费。一旦有，S3 与 S4 之间必须插一屏「再加 X 元才送到」，主流程从 6 屏变 7 屏——这是最容易破坏「步骤少」的地方。
  • 已付款的订单谁能取消。付款前自助取消已画在 S5；付款后是老人自己点、还是必须店长同意？决定 S5 要不要保留那个红色按钮。
  • 定位失败又没存过小区时，S0 显示什么。现在 S0 的药丸和店铺图都直接写「阳光生鲜 · 文三路」，前提是已经绑过地址。第一次打开的那一屏还没画——尤其要定：没有店的时候，药丸里写什么。
  • 谁替老人做首次绑定。「订单」「我的」两个 Tab 还没画。认出你是谁依赖家属先绑手机号与地址，这条前置流程在本原型之外，缺了它老人根本到不了 S0。订单页要按什么状态口径排（已告诉店里 / 店里备好了 / 可以拿了 / 已完成），我的页要不要放地址与家属绑定——这两屏不定，底栏就是三个空壳入口（加上铃铛是四个），点进去会白屏。
  • 购物车空态长什么样，以及首页的空态。底栏常驻之后，老人会在什么都没买的时候点进购物车，首页也会在没买任何东西时显示「已经买了 0 样」这种怪话。T1 画的是「3 样」这一种状态；空篮子是提示「还一样都没挑，去上面挑几样」并把 dock 那句换掉，还是直接不给 dock？
  • 角标算一家店还是所有店。PRD §3.5 定了不同店的菜不能并成一单，那底栏角标写「3」到底只指当前这一家，还是把所有店的篮子加起来？若相加，等于用图标暗示老人「这些能一起结」。本原型先按当前所在店计数——这也正是首页 dock 那句「已经买了 3 样」的口径。
